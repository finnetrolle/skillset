## Итоги аудита 07.10.2026

Все 44 решения записаны в реестре аудита. Репозиторий содержит ровно 27
сохранённых пакетов, 277 файлов; исключённые 17 пакетов отсутствуют в `skills/`
и каталоге источников. `make check test catalog-check` прошёл: 22 локальных

в grill-me, epic-to-issues, analyze-via-sonar и cavecrew.

удаления и frontend-skill для сохранения только в Codex; содержимое всех 16
совпадает с tracked manifests. Lavish уже отсутствует.

Эта предварительная проверка не меняла установленные копии. Итоговый перенос,
удаление исключённых копий и публикация изменений аудита ожидают команды
владельца; перед переносом состояние будет проверено повторно.

## Сверка security-best-practices с OpenAI 07.10.2026

Проверен официальный пакет `skills/.curated/security-best-practices` в
`openai/skills`, HEAD `49f948faa9258a0c61caceaf225e179651397431`.
Все 13 файлов локального пакета совпадают по байтам и executable bit с
первоисточником, дополнительных файлов нет. Содержимое пакета уже актуально;
изменены только данные происхождения, отображение источника в каталоге и
документация будущей сверки. Исходный `baseline_files` сохранён без изменений.

Публичная команда `upstream-diff --source openai --skill security-best-practices`
подтвердила совпадение pin и актуального HEAD, пустые upstream patch и local
instruction patch. `make check test catalog-check` прошёл, включая 22 теста
менеджера и отчёта. Bundled `quick_validate.py` подтвердил валидность пакета.
Установленные копии не менялись. Поведенческий прогон не повторялся, поскольку
инструкции и справочники не изменились.

Проверка менеджера проходит через его публичный CLI в временных каталогах.
Сценарии: ресурсы и executable modes; зависимые пакеты; idempotence; точные
backup/rollback; ручные правки; ранний отказ без частичной установки; миграция
старых копий без удаления чужих скиллов; dry-run без создания target; ошибки
аргументов и метаданных; потеря процесса во время install/rollback; повреждённый
backup; запрет замены aliases. Forced rollback также сохраняет вытесняемые
ручные правки. Upstream test использует локальный Git-репозиторий с двумя
коммитами и проверяет сохранение pin и пользовательской адаптации.

Regression test отчёта создаёт синтетические SQLite/JSONL журналы Codex и
Claude Code. Проверяет учёт .system, --all, дедупликацию и атрибуцию usage.
Реальные пользовательские журналы не используются в тестах.

Независимый поведенческий прогон в изолированном fixture:

| Скилл | Сценарий | Наблюдение |

| grill-me | Уже согласован CSV import, требуется найти пробелы | Принятые решения сохранены, один вопрос о partial/atomic import. Проверен первый ход, не полный диалог. |
| domain-modeling | Совет о customer/client, CONTEXT.md существует, писать запрещено | Использован канонический customer; CONTEXT не менялся, glossary/ADR не создавались. |

Прогон также обнаружил неоднозначные безусловные фразы об обновлении
GLOSSARY.md. Они заменены условными инструкциями с приоритетом CONTEXT.md и
разрешённого scope. В reference writing-for-agents разделены Codex и Claude
invocation controls.
Повторное чтение обновлённых справочников подтвердило отсутствие этих
противоречий; runtime discovery обоих хостов отдельно не проверялся.

HTTP fixture baseline в sandbox не запустился из-за запрета bind localhost.
Это ограничение поведенческого прогона, не подтверждение работоспособности
реальной /health реализации. В этом репозитории она не менялась.

`make check` проверяет упаковку всего набора: YAML, имена, файлы, UI icons,
прямые и транзитивно связанные Markdown references. Это не полный runtime
тест всех сторонних workflow. Некоторые скиллы требуют Docker, JVM/Gradle,
браузер, соответствующий plugin или Claude-specific hooks; их ресурсы
сохранены, но такие среды не устанавливаются менеджером.

На исходном снимке из 44 пакетов bundled quick_validate.py пропустил 42. Для kdoc и lavish
его ограниченный allowlist отвергает сохранённые host-specific поля
user-invocable и argument-hint/author. Эти исходные поля не удалены ради
валидатора: собственная проверка сохраняет совместимость набора с обоими
хостами и проверяет обязательные name/description и ресурсы.

## Самодостаточный cavecrew

Пакет включает investigator, builder, reviewer и общий контракт. Маршрутизация
использует доступный механизм делегации и зарегистрированные типы текущего
хоста; отдельные Claude presets, hooks и model overrides не требуются.
Убраны неподтверждённые проценты экономии. Краткий вывод сохраняет ограничения,
частичные изменения и фактические результаты проверок.

Проверки упаковки, quick_validate и catalog-check успешны. Публичный CLI
доставил шесть файлов во временный target с точным совпадением содержимого
и executable mode; повторная установка unchanged, rollback успешен.
Исходный provenance manifest сохранён.

Независимая проверка использовала четыре изолированных fixtures:

- Codex investigation: одно определение и два подтверждённых вызова;
  импорт и текстовое упоминание не посчитаны вызовами.
- Ревью без делегации: найден регресс, отклоняющий разрешённый limit=0.
- Совместная правка трёх файлов: выбран общий agent scope, без дробления
  задачи между двухфайловыми builders.
- Claude builder: план использует зарегистрированный general-purpose;
  роль исполнена проверяющим агентом в fixture. Публичная CLI сначала вернула
  null для count=0, regression test дал RED, после правки прошли три теста.

Изменены только два разрешённых файла fixture. Схемы хостов являются
тестовыми данными; реальный Claude runtime и вложенная делегация не запускались.
Это проверка решений и выполнения роли, а не интеграция всех версий хостов.
Установленная личная копия ожидает переноса после аудита.
