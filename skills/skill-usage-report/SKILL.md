# Отчёт об использовании скиллов

Запусти `python3 scripts/report.py` из папки этого скилла. По умолчанию анализируются последние 30 суток в часовом поясе Europe/Moscow и все локальные задачи разработки в `~/dev`, `~/.no-mistakes/worktrees` и репозиториях с Git remote. Пользователь может задать `--days`, `--from`, `--to`, `--tz` или повторить `--dev-root PATH`. Не отправляй журналы во внешние сервисы.

Верни таблицу из отчёта и короткий вывод: какие скиллы использовались чаще, где велики затраты на одно применение, какие строки имеют мало наблюдений. Если пользователь просит файл, передай `--output PATH` и дай ссылку на созданный Markdown. При необходимости изучить машинные данные передай `--json PATH`.

Считай применением явный вызов `Skill` в Claude Code или чтение конкретного `<skill>/SKILL.md` в Codex/Claude Code. Повторные чтения одного скилла в рамках одного хода считаются одним применением. Таблица считает токены ответов и прошедшее время **после** активации скилла до следующей активации или конца хода. Это атрибуция этапу работы, а не точная стоимость инструкций скилла. Интервалы разных скиллов не пересекаются; подготовка до активации не учитывается. Время включает ожидания и не равно времени человека. Не называй низкое число токенов или минут доказательством пользы скилла: сложность задач различается, и журналы не содержат контрфактического сравнения. Если данных не хватает, укажи покрытие и `н/д`, не подменяя ноль отсутствием данных.

После построения проверь период, покрытие источников и предупреждения в отчёте. Не показывай пользователю сырые сообщения или команды из журналов: в них могут быть личные данные.
