# Сохранение результатов приёмки

Этот контракт используют implement, verify-changes, two-axis-review и what-next.
Он отвечает за сохранность и передачу доказательств; команды проверок и условия
повторного использования задают проект и соответствующий runner.

## Где и когда сохранять

Используй существующее постоянное локальное хранилище evidence проекта. Если
его нет, для Git-проекта выбери каталог из `git rev-parse --git-path acceptance-evidence`.
Он находится вне `build`, временных каталогов и tracked
документации. В проекте без Git используй его постоянный локальный каталог
артефактов. Укажи фактический путь в передаче работы.

На каждое завершение проверки или review-оси создавай отдельный каталог внутри
evidence текущей задачи. Сохраняй его сразу после получения конечного результата,
до следующей команды, которая может перезаписать отчёты, очистки build или
передачи работы другому агенту. Опубликованные пакеты не перезаписывай: новая
проверка или remediation создаёт новый пакет со ссылкой на предыдущий.

Если runner уже сохраняет независимые копии отчётов, используй их и добавь
ссылки в пакет вместо повторного копирования. Иначе сохрани самостоятельные
копии нужных файлов и деревьев отчётов, сохраняя относительные пути; symlink
или hardlink на рабочий output не обеспечивает сохранность. Сверь состав и
контрольные суммы копии с исходными отчётами и, когда доступны, digest из run.
Сначала заверши копирование, затем опубликуй manifest пакета. При ошибке явно
отметь неполноту и сохрани доступные материалы; готовность пакета не заявляй.

## Что передавать

Один manifest связывает:

- задачу, точный source path/revision и последующие согласованные уточнения;
- base, проверенное состояние, scope и существующие посторонние изменения;
- verification session, gate, команду, конечный exit и run ID;
- input/toolchain/environment declarations или ссылки на сохранённые записи;
- оригинальные пути отчётов, пути сохранённых копий и их контрольные суммы;
- полную таблицу criterion -> evidence; для семантического ревью - отдельные
  отчёты Standards и Spec, их baseline, findings и remediation wave;
- недостающие проверки и действия завершения с ответственным этапом.

Заполняй только применимые поля: у семантического ревью без запуска команды
нет выдуманного exit или run ID. Ссылайся на доступные канонические источники
вместо повторения их содержимого.
Память чата и короткое финальное сообщение не заменяют сохранённые отчёты.
Секреты, env-файлы и raw environment dumps в пакет не включай. Если нужна
редактированная копия отчёта, явно обозначь её как производную: её checksum
не является checksum исходного отчёта.

Сохраняй также доступные отчёты неуспешной проверки, включая причинный RED.
Фиксируй точную причину failure и полноту материалов: ненулевой exit сам по себе
не доказывает воспроизведение дефекта. Отсутствующий отчёт отмечай как отсутствующий;
не подставляй отчёт другого запуска. Failure, timeout и infrastructure failure
сохраняют свой исход и не становятся PASS после архивирования.

## Как использовать сохранённое

При продолжении работы сначала прочитай переданный manifest и нужные отчёты.
Отдельно установи три факта: что исторически проверено, какие результаты
применимы сейчас и какие действия закрытия задачи остались.

Для текущего PASS проверь целостность сохранённой evidence, совпадение scope и
входов, toolchain/environment и действующую session/freshness policy. Сохранение
архива само по себе не разрешает reuse. Выполни обязательный status/lookup
runner, если этого требует проект. Если старый runner проверяет только рабочие
outputs и показывает corrupt после их перезаписи, архив сохраняет историческое
доказательство, но не отменяет этот verdict и не даёт права объявить current PASS.

Повторяй проверки при необходимости получить актуальный результат, а не чтобы
заново создать уже сохранённую историю. При передаче укажи путь к manifest,
принятые и неприменимые результаты с причинами и оставшиеся действия. При
read-only ревью разрешено сохранить собственный локальный evidence-пакет;
исходный код, требования и существующие пользовательские файлы остаются нетронутыми.
