# Формат поблочного отчёта

Отчёт должен быть самодостаточным: читатель видит охват, метод, все тезисы и основания для каждого вердикта, не возвращаясь к рабочим заметкам исследователя.

## Заголовок и паспорт проверки

Начни с:

```markdown
# Фактчекинг тезисов воркшопа

- Дата проверки: YYYY-MM-DD
- Вход: файл, список файлов или «текст из сообщения»
- Блоков: N
- Извлечено тезисов: N
- Внешне проверяемых: N
- Не фактологических / локальных: N
- Повторов между блоками: N
- Осталось без достаточных данных: N
```

После паспорта добавь 2–4 предложения о главных рисках: какие формулировки чаще всего нуждаются в оговорках, есть ли устаревающие продуктовые утверждения и где потребуются внутренние источники.

## Раздел блока

Для каждого блока используй одинаковую структуру:

```markdown
## Блок 01. Исходный заголовок

Краткое содержание: одно предложение.

| ID | Тезис | Тип | Достоверность | Уверенность | Обоснование | Подтверждающие ссылки | Опровергающие или ограничивающие ссылки | Рекомендация |
|---|---|---|---|---|---|---|---|---|
| B01-T01 | Один атомарный тезис | Внешний факт | ✅ Подтверждён | Высокая | Краткое сопоставление тезиса с доказательством | `[Название источника](прямой URL)` | — | — |
```

### Требования к ячейкам

- **Тезис:** точная короткая цитата либо близкая к тексту нейтральная формулировка без усиления смысла.
- **Тип:** одно значение из шкалы; при необходимости укажи вторичный тип после `/`.
- **Достоверность:** только один нормализованный вердикт из шкалы.
- **Уверенность:** `Высокая`, `Средняя`, `Низкая` или `Неприменимо`.
- **Обоснование:** 1–3 предложения о том, что именно доказывают источники и где проходит граница вывода. Не пересказывай всю статью.
- **Ссылки:** используй описательные Markdown-ссылки на прямые страницы. Несколько ссылок разделяй `<br>`. При локальном доказательстве давай кликабельный абсолютный путь с номером строки, если он известен.
- **Рекомендация:** действие над тезисом. Если нужна правка, добавь `Вариант: «…»`. Если полезной правки нет, ставь `—`.

Для `🔵 Не фактологический` допустимо поставить `—` в обеих колонках источников, но объясни, почему это правило, намерение или эвристика. Если рекомендация обосновывается проверяемым фактом, вынеси этот факт отдельной строкой и проверь его.

Для `⚪ Недостаточно данных` не подставляй тематически близкую ссылку. В обосновании кратко укажи, какие авторитетные типы источников были проверены и чего не хватило; в рекомендации предложи внутренний документ, эксперимент или более узкую формулировку.

После таблицы при необходимости добавь:

```markdown
Замечания по блоку:

- повторяющаяся проблема формулировок;
- пропущенное условие или противоречие внутри блока;
- наиболее важная правка для рассказчика.
```

Не повторяй в замечаниях содержание каждой строки.

## Межблочные повторы

После всех блоков добавь таблицу только при наличии повторов:

```markdown
## Повторы и пересечения

| Канонический тезис | Повторы | Рекомендация по структуре воркшопа |
|---|---|---|
| B02-T03 | B05-T01, B09-T04 | Оставить полное объяснение в блоке 02, позже использовать короткую отсылку |
```

## Итоговые рекомендации

Заверши отчёт приоритизированным списком:

1. критические фактические исправления;
2. формулировки, требующие оговорки или даты;
3. тезисы, которым нужны внутренние доказательства;
4. структурные повторы, которые стоит сократить;
5. сильные тезисы, которые можно оставить без изменений.

Не переписывай весь воркшоп, если пользователь просил только фактчекинг. Полный обновлённый текст создавай отдельным артефактом только по явной просьбе.
