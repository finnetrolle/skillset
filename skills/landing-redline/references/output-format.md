# Output Format

Use this order unless the user explicitly asks for a different format.

## 1. Verdict

- Write two to four blunt sentences.
- Name the main problem before naming secondary issues.
- Avoid praise-first framing.

## 2. Inventory Summary

- State which sections or files were audited.
- Note missing text sources, hidden strings, or gaps in the inventory.

## 3. Findings By Priority

For each finding include:

- priority: `P1`, `P2`, or `P3`
- location: section, component, or file
- problem: what is wrong
- impact: why it hurts clarity, trust, or conversion
- direction: what should change

## 4. Prioritized Change Plan

- List the smallest set of changes that will produce the biggest lift.
- Separate messaging fixes from wording fixes from structure fixes.

## 5. Proposed Rewrites

- Rewrite high-leverage copy first: headline, subhead, CTA, proof, closing section.
- Offer alternatives only when there is a meaningful strategic choice.
- Keep replacements concrete and ready to paste.

## 6. Implementation Notes

- Map changes to files or sections when code edits are needed.
- If direct edits were requested, keep the audit summary short but still explicit.
